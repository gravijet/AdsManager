Integration

So bindest du das Werbe-Widget auf einer Website ein.

1. iFrame einbetten

Ersetze SITE_KEY mit dem Key der jeweiligen Website (siehe „Websites"-Tab).

<iframe
  src="https://example.invalid/?site=SITE_KEY"
  width="360" height="280"
  style="border:0;"
  allow="autoplay"
></iframe>

2. Auf die Belohnung reagieren

Das Widget sendet postMessage-Events an die einbettende Seite.

window.addEventListener("message", (event) => {
  if (event.data?.type === "werbung:reward") {
    // Belohnung im Frontend freischalten.
    // event.data.adId kann null sein (Fallback "sofort gewähren").
    // event.data.rewardToken: einmal verwendbares Token für die
    // serverseitige Bestätigung (siehe Punkt 3) — kann fehlen, wenn
    // der Viewer keine Third-Party-Storage-Events erlaubt.
  }
  if (event.data?.type === "werbung:click") {
    // Nur bei Klick-Aktion "postmessage": event.data.payload
  }
  if (event.data?.type === "werbung:ready") {
    // Widget ist geladen.
  }
});

// Optional: Widget von außen zurücksetzen (z.B. neuer Versuch)
iframeEl.contentWindow.postMessage({ type: "werbung:reset" }, "*");

3. Belohnung serverseitig bestätigen (empfohlen)

Ein postMessage im Browser lässt sich mit den Entwicklertools fälschen. Für echte Belohnungen (Guthaben, Freischaltungen) sollte das eigene Backend der einbettenden Website das rewardToken serverseitig gegenprüfen, bevor es die Belohnung gutschreibt. Das Token ist 10 Minuten gültig und genau einmal einlösbar. 

GET https://example.invalid/api/verify?token=TOKEN

→ { "valid": true, "adId": "...", "siteId": "...", "viewerId": "...", "issuedAt": "..." }
→ { "valid": false, "reason": "already_consumed" | "expired" | "not_found" }

Alternativ kann pro Website ein Webhook hinterlegt werden (Feld „Webhook-URL" im Websites-Tab) — bei jedem Abschluss sendet Werbung dann serverseitig einen POST mit { event: "reward", token, adId, siteId, viewerId, timestamp } an diese URL. Zustellung ist Best-Effort (kein Retry); /api/verify bleibt die verlässliche Quelle, falls eine Zustellung verloren geht.

Hinweise

  • Klick-Aktion „Seite oben ersetzen" funktioniert nur, wenn der iFrame kein sandbox-Attribut ohne allow-top-navigation hat.
  • Frequenzbegrenzung läuft über localStorage im iFrame — private Browserfenster oder deaktiviertes Storage setzen sie außer Kraft.
  • Ohne ?site=-Parameter erhält der Betrachter Anzeigen aus dem globalen Pool (keine Website-spezifischen Regeln, keine site-exklusiven Anzeigen).
  • Geo-Targeting nutzt das Herkunftsland aus dem Cloudflare-Edge-Request; Geräte-Targeting wird serverseitig aus dem User-Agent abgeleitet.
